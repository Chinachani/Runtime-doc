# QQ Runtime 插件开发指南

面向插件开发者的完整参考：从最小可运行插件到调用 Runtime 全部能力。
本文以当前 Runtime 实现（`runtime/plugin_sandbox.py` / `runtime/plugin_packages.py` / `runtime/plugins.py`）为准；
插件系统的设计约束、信任模型和上传生命周期见 `plugin-development.md`。

- 官方演示插件：`examples/plugin.demo.guide/`（覆盖命令/事件/任务/积分/网络/卡片/通用配置读写/页面 Action RPC）

---

## 1. 快速开始

一个插件 = 一个 ZIP 包，至少包含 `plugin.toml` 和入口 Python 文件：

```toml
# plugin.toml
[plugin]
id = "plugin.hello"
name = "你好插件"
version = "0.1.0"
entrypoint = "hello:setup"

[[commands]]
name = "hello"
category = "demo"
description = "打招呼"
```

```python
# hello.py
def setup(context):
    async def handler(ctx, args):
        return f"你好！你的 OpenID 是 {ctx.sender_id}"
    context.register_command("hello", handler, category="demo", description="打招呼")
    return None          # 也可返回带 close() 的对象
```

打包上传：

```bash
cd 插件目录 && zip -r ../plugin.hello.zip plugin.toml hello.py
```

管理台 → 插件管理 → 上传 ZIP → 开启开发者模式 → 启用。
上传后进入 `pending_review`（开发者模式关闭时不会执行）；启用前 Runtime 会校验包结构、路径安全、声明一致性。

## 2. plugin.toml 字段参考

```toml
# 顶层字段（不能放进任何 [table] 内）
dependencies = []                      # 依赖包名；必须 ∈ Runtime allowlist，默认为空（一般留空）
permissions = ["plugins.manage"]       # 管理页/接口权限（RBAC 权限名）
capabilities = ["chat.send", "network"] # 进程能力声明（见第 5 节；与 permissions 互不通用）
builtins = ["runtime.pay"]             # 需要调用的内置插件（见第 8 节）

[plugin]
id = "plugin.demo"                     # 唯一 ID：字母开头，[a-zA-Z0-9_.-]，3-64 字符
name = "演示插件"
version = "0.1.0"
entrypoint = "demo:setup"              # 模块:函数；setup(context) 在 worker 进程执行

[[commands]]
name = "demo"                          # 单词命令，冲突会拒绝加载
category = "demo"
description = "主命令"

[[events]]
type = "*"                             # "*" 全量事件，或具体类型（如 "message"）

[[tasks]]
id = "cleanup"                         # 任务 ID：字母开头
interval_seconds = 3600

[[pages]]
id = "home"
title = "管理页"
path = "pages/index.html"              # 包内相对路径
```

校验规则要点：

| 字段 | 约束 |
|---|---|
| id | `[a-zA-Z][a-zA-Z0-9_.-]{2,63}`，唯一 |
| version | 非空，≤32 字符 |
| commands[].name | `[a-zA-Z0-9_-]{1,32}`，包内唯一，注册名必须与声明一致 |
| events[].type | 非空 ≤64 字符，包内唯一 |
| tasks[].id / interval_seconds | 字母开头 ID；间隔 ≥1 秒 |
| pages[].id / path | 字母开头 ID；路径禁止 `..` 与绝对路径 |
| capabilities | `[a-zA-Z][a-zA-Z0-9_.:-]{0,63}`；也接受 `[plugin] capabilities` 嵌套写法 |
| builtins | 内置插件 ID 列表 |

## 3. 入口与生命周期

```python
def setup(context):
    """
    在插件 worker 进程中执行（进程隔离）。
    - 注册命令/事件/任务必须在 setup 内完成，且与 plugin.toml 声明一致，
      注册未声明的名字会直接抛错。
    - 返回 None，或返回实现了 close() 的对象：插件停用/卸载/Runtime 关闭时
      会调用 close()（支持同步或 async）。
    """
    plugin = MyPlugin(context)
    return plugin

class MyPlugin:
    def close(self):
        """释放定时器、文件句柄、子进程等资源。"""
```

- `setup` 里就可以调用全部能力门面（积分、消息、网络等）。
- 命令/事件处理器都是协程：`async def handler(ctx, args)` / `async def handler(ctx)`。
- 任务处理器无参：`async def task()`；Runtime 按声明间隔调度。
- 插件被停用或 Runtime 授权失效时，命令/事件/任务会先于 worker 关闭被注销。

## 4. PluginContext API 参考

`setup(context)` 收到的 `context` 是唯一入口，**worker 进程内拿不到 Runtime 对象**，一切能力走门面：

### 注册类

| 方法 | 说明 |
|---|---|
| `context.register_command(name, handler, category="", description="")` | 注册命令；handler 签名 `async (ctx, args: list[str]) -> str \| Card \| None` |
| `context.register_event_handler(event_type, handler)` | 注册事件处理器；签名 `async (ctx)` |
| `context.register_task(task_id, interval_seconds, handler)` | 注册周期任务；签名 `async ()` |

### 目录

| 属性 | 说明 |
|---|---|
| `context.config_dir` | 插件配置目录（卸载时可保留） |
| `context.data_dir` | 插件数据目录（持久化业务数据；跨重启保留） |

把 JSON 状态写在这两个目录下；不要写插件安装目录（升级会被替换）。

### 能力门面

| 属性 | 方法 | 需要能力 |
|---|---|---|
| `context.qq.send_text(conversation_id, scene, content)` | 发文本 | `chat.send` |
| `context.qq.send_card(conversation_id, scene, card)` | 发卡片 | `chat.send` |
| `context.qq.send_media(conversation_id, scene, file_info)` | 发媒体（文件） | `chat.send` |
| `context.qq.send_channel_media(conversation_id, scene, image=…/file_image=…)` | 频道图片 | `chat.send` |
| `context.qq.upload_media_file(request, path, **kwargs)` | 分片上传 | `chat.send` |
| `context.points.balance(identity, point_type="default")` | 查余额 | 无 |
| `context.points.credit(identity, amount, *, reason, actor, operation_id)` | 加积分 | `points.manage` |
| `context.points.debit(identity, amount, *, reason, actor, operation_id)` | 扣积分 | `points.manage` |
| `context.media.prepare(scene, target_id, file_type, path)` | 上传元数据（唯一接受 Path） | 无 |
| `context.media.cached_file_info(request)` | file_info 缓存 | 无 |
| `context.audit.record(actor=, source=, module=, action=, target=, result=, …)` | 审计 | 无（限频 120 次/分） |
| `context.chat.get_conversation / list_conversations / list_messages / mark_read` | 聊天历史 | `chat.read` / `chat.write` |
| `context.md.render_card(value, ctx)` | 渲染 MD 卡片 | 无 |
| `context.builtin(plugin_id)` | 调用内置插件导出 API（第 8 节） | manifest `builtins` 声明 |

说明：

- `actor` 会被父端强制改写为 `plugin:<你的插件 ID>`，不能伪造他人。
- `operation_id` 是幂等键：同一 `operation_id` 的积分操作只生效一次，用于订单/防重放。
- 积分金额是字符串或 Decimal（如 `"1.50"`），内部按 0.01 最小单位整数存储，禁止 float。
- 发送文件的完整链路（三步，缺 `upload_media_file` 会报 "file_info is required"）：
  ```python
  request = await context.media.prepare(scene, target_id, 4, path)   # 本地摘要元数据
  uploaded = await context.qq.upload_media_file(request, path)       # 分片上传到 QQ
  file_info = uploaded["file_info"]                                  # 短时有效的上传凭据
  await context.qq.send_media(target_id, scene, str(file_info))      # 发送
  ```
  `path` 必须位于你的 `data_dir` 内（父端做路径映射与越权检查）；
  文件发送仅支持 c2c/group 场景（channel/guild_direct 用
  `send_channel_media(file_image=字节)` 发图片）。完整实现参考
  `plugin.drawimg.service` 的 `_send_image` 或 `plugin.word2ppt` 的 `_send_file`。
- 审计有预算限制（每分钟 120 条），不要在循环里刷审计。

## 5. 申请权限：permissions 与 capabilities 的区别

两个字段互不相通，各自守一道门：

| 字段 | 守什么 | 典型值 |
|---|---|---|
| `permissions` | **管理页/接口**（RBAC）：`[[pages]]` 的访问权、桥接 API 的读权限 | `plugins.manage`、`permissions.manage`、`points.manage` |
| `capabilities` | **worker 进程能力**：决定服务调用白名单能否通过（映射到 `chat.send`、`points.manage`、`network` 等） | `chat.send`、`chat.read`、`points.manage`、`network` |

原则：**最小授权**。只发消息就只声明 `capabilities = ["chat.send"]`；
要写积分账本才加 `points.manage`；`runtime.admin` 永远不会被视为通配符。

未声明能力时的表现（举例）：调用 `qq.send_text` 但没有 `chat.send` → 父端抛
`Plugin capability requires manifest permission: chat.send`。

## 6. 命令、事件与回复

```python
async def handler(ctx, args: list[str]) -> str | Card | None:
    # ctx 是 MessageContext：
    #   sender_id / user_id / member_openid / group_id / channel_id / guild_id
    #   scene ("c2c"|"group"|"channel"|"guild_direct") / conversation_id
    #   is_admin / member_role / message_id / attachments / raw_payload
    return "文本回复（可直接 return，Runtime 负责发送）"
```

- 命令处理器 `return` 的字符串/卡片由 Runtime 自动回复给用户；
  需要主动多次发送时用 `await context.qq.send_text(ctx.conversation_id, ctx.scene, text)`。
- 群聊/at 变量、场景限制等由 Runtime 统一处理，插件不要自行调用 botpy。
- 事件处理器（`type="*"`）用于附件接收等场景：从 `ctx.attachments` / `ctx.raw_payload`
  递归扫描附件 URL（QQ 会给文件一个多媒体下载 URL），用 `httpx`（需 `network` 能力）下载。

发送卡片：

```python
from runtime.models import Button, Card

card = Card(
    title="我的面板",
    markdown="**演示**\n\n这是 Markdown 正文",
    rows=[
        [Button(label="按钮一", command="/demo one"),
         Button(label="危险", command="/demo reset", style="danger")],
    ],
)
return card   # 或 await context.qq.send_card(ctx.conversation_id, ctx.scene, card)
```

`Button` 常用字段：`label`、`command`（点击后下发的指令）、`style`（normal/primary/danger/success）、
`permission`（0 指定用户 / 1 仅管理员 / 2 所有人 / 3 指定身份组）、`enter`、`reply`、
`expires_after_seconds` 等，完整定义见 `runtime/models.py`。

群聊里把按钮限定为触发者本人（避免他人代触），用 `permission=0` + `specify_user_ids`：

```python
Button(label="查我的积分", command="/guide me",
       permission=0, specify_user_ids=(str(ctx.sender_id),))
```

跳转链接按钮（`action_type=0`，`command` 填 URL）不涉及命令权限，无需限定。

## 7. 网页注册与管理页通信（零改框架）

`[[pages]]` 声明页面后，Runtime 生成同源/沙箱 URL `/api/plugins/<id>/pages/<page_id>`，
管理台在“插件页面”菜单里渲染；页面访问需要 manifest `permissions` 中的任一权限（未声明默认 `plugins.manage`）。

外部插件页面运行在 opaque-origin iframe（CSP `connect-src 'none'`），**不能直接 fetch Runtime 接口**，
必须通过消息桥 SDK（`RuntimePluginBridge`）与宿主进行通信。

> [!IMPORTANT]
> **开发规范：第三方插件绝不需要在框架 `runtime/web.py` 中写任何端点！**
> 框架已提供全套通用端点，插件页面直接调用桥的内置方法即可搞定所有业务需求。

### 框架提供的通用 API 矩阵

| 功能 | 后端通用端点 | 桥 SDK 便捷方法 | 说明 |
|---|---|---|---|
| **读取快照** | `GET /api/plugin/{id}/page-data/{name}` | `RuntimePluginBridge.getPageData(name)` | 读取插件在 `data_dir` 下写入的 `{name}.json` 快照文件 |
| **读取配置** | `GET /api/plugin/{id}/config` | `RuntimePluginBridge.getConfig()` | 读取插件在 `config_dir` 下保存的 `config.json` |
| **保存配置** | `POST /api/plugin/{id}/config` | `RuntimePluginBridge.saveConfig(cfg)` | 自动安全写入 `config.json`，并自动更新快照与命令队列 |
| **执行动作** | `POST /api/plugin/{id}/action/{action}` | `RuntimePluginBridge.callAction(action, payload)` | 直接向插件沙箱 Worker 发起 RPC 动作并同步等待结果 |

---

### Python 端处理页面 Action 动作

在插件主类中，只需定义 `on_page_action`（或用 `context.register_action` 注册特定动作）：

```python
class MyPlugin:
    def __init__(self, context):
        self.context = context

    async def on_page_action(self, action: str, payload: dict) -> Any:
        """接收管理页面派发的自定义动作并返回结果。"""
        if action == "fetch_models":
            api_url = payload.get("api_base_url")
            # 外部插件独立在沙箱中发起网络请求获取模型列表
            models = await self._fetch_upstream_models(api_url)
            return {"models": models}

        if action == "test_connection":
            # 测试连通性并返回状态
            ok = await self._test_network()
            return {"connected": ok}

        raise ValueError(f"未知动作: {action}")
```

### 页面前端 HTML 标准模版

外部插件页面在 opaque-origin iframe 下，需内联桥 SDK：

```html
<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <title>插件管理面板</title>
  <script>
  // 必须声明你的插件 ID，SDK 助手方法会自动拼装通用路由
  window.__PLUGIN_ID__ = "plugin.demo.guide";
  </script>
  <!-- 直接将 runtime/static/assets/js/plugin-sdk.js 内联在页面头部 -->
  <script>
  (function(global){/* plugin-sdk.js 源码 (见 examples/plugin.demo.guide/pages/index.html) */})(window);
  </script>
</head>
<body>
  <h1>我的插件面板</h1>

  <!-- 1. 读取快照 -->
  <button onclick="refreshData()">刷新统计</button>
  <div id="statsBox"></div>

  <!-- 2. 保存配置 -->
  <input id="apiKey" placeholder="输入 API Key">
  <button onclick="saveMyConfig()">保存配置</button>

  <!-- 3. 执行动作 -->
  <button onclick="triggerWorkerAction()">拉取模型列表 (RPC)</button>

  <script>
  async function refreshData() {
    // 自动请求 GET /api/plugin/plugin.demo.guide/page-data/page_overview
    const data = await RuntimePluginBridge.getPageData("page_overview");
    document.getElementById("statsBox").textContent = JSON.stringify(data);
  }

  async function saveMyConfig() {
    const key = document.getElementById("apiKey").value;
    // 自动请求 POST /api/plugin/plugin.demo.guide/config
    const res = await RuntimePluginBridge.saveConfig({ api_key: key });
    alert(res.message || "已保存");
  }

  async function triggerWorkerAction() {
    // 自动请求 POST /api/plugin/plugin.demo.guide/action/fetch_models 并派发给 Worker
    const res = await RuntimePluginBridge.callAction("fetch_models", { timeout: 10 });
    console.log("Worker 响应:", res);
  }

  window.addEventListener("load", refreshData);
  </script>
</body>
</html>
```

桥的安全边界：
- 严格受限路径：宿主只放行当前插件所属的 `/api/plugin/<id>/*` 命名空间，隔离恶意访问。
- CSRF 与登录态：写操作（配置保存与 Action RPC）由宿主携带管理员 Session 与 CSRF 执行，外部 iframe 无法窃取 Token 或 Cookie。
- 沙箱隔离：Worker 执行 Action 出现任何崩溃或超时，均会被沙箱捕获并返回格式化错误，绝不会拖垮 Runtime 主服务。

## 8. 调用内置插件（builtins 桥）

第一步：`plugin.toml` 顶层声明需要的内置插件：

```toml
builtins = ["runtime.pay"]
```

第二步：在代码里通过 `context.builtin(<目标 ID>)` 使用。**未声明的目标、未导出的方法、
已停用的内置插件都会在 Runtime 父端被拒绝**，并且每次调用都会写审计日志。

当前已导出的内置插件 API：

| 内置插件 | 方法 | 说明 |
|---|---|---|
| `runtime.pay` | `create_payment(source_plugin, external_id, owner_key, subject, amount, points, point_type="default", payment_type="alipay", …)` | 创建支付订单（567 支付），返回订单信息 |
| `runtime.pay` | `query_payment(reference)` | 查询订单状态 |
| `runtime.pay` | `close_payment(reference)` | 关闭未支付订单 |
| `runtime.pay` | `refund_payment(reference, amount=None)` | 全额/部分退款 |
| `runtime.pay` | `exchange(identity, rule_id, amount)` | 积分兑换 |

示例（创建充值订单并展示订单卡，完整实现见 `examples/plugin.demo.guide/`）：

```python
pay = context.builtin("runtime.pay")
order = await pay.create_payment(
    source_plugin=context.plugin_id,     # 你的插件 ID
    external_id="order-20260905-001",    # 你方业务幂等号
    owner_key=ctx.sender_id,             # 积分身份：支付成功后积分自动入账到这里
    subject="100 积分充值",
    amount="1.00", points="100.00",
)
order_id = order.get("order_id") or order.get("id")
pay_url = order.get("pay_url") or order.get("url") or order.get("pay_info") or ""
```

要点：

- **入账是自动的**：`runtime.pay` 的轮询任务确认支付成功后，会把 `points`
  自动 `credit` 到 `owner_key`（幂等键 `payment:<订单ID>`）。插件**不要**再
  自己 `credit` 一遍，否则会重复入账。
- **owner_key 必须是积分身份**：与 `context.points.balance(...)` 查询用的
  身份一致（通常是 `ctx.sender_id`），否则到账后用户查不到。
- **订单卡展示**：`pay_url` 构造跳转按钮（`Button(label="💳 立即付款",
  command=pay_url, action_type=0, style="primary")`，action_type=0 为链接
  按钮），配合"查询订单"按钮（`pay.query_payment(order_id)`，状态
  `local_status` 为 `paid`/`pending`）；需要扫码时用本地 `qrcode` 库把
  `qrcode`/`pay_url` 渲染成 PNG 后经 `media.prepare` + `qq.send_media`
  发送（参考 `plugins/plugin.drawimg.service` 的 `_send_pay_qr_image`）。
- 同一用户未支付订单有上限（默认 3 单），超限时 `create_payment` 会抛
  "active payment limit"，提示用户先完成或等待超时关闭。

其他内置插件（na 等）尚未定义沙箱桥导出面；Runtime 侧调用
`registry.register_builtin_api(plugin_id, methods)` 注册后即可按同样方式声明使用。

## 9. 打包、上传与调试

打包：

```bash
cd plugins/plugin.<name>
zip -r ../plugin.<name>.zip plugin.toml *.py pages
```

上传与启用：管理台 → 插件管理 → 上传 ZIP（默认 ≤50MiB）→ `pending_review`
→ 开发者模式开启后可启用（生产环境需接入信任校验）。同一 ID 重新上传即升级，
Runtime 会自动停用旧版本、校验并重启 worker。

调试：

- 管理台插件列表会显示状态（`enabled` / `load_failed` / `disabled`）；加载失败时
  查看错误详情（通常是 plugin.toml 校验、命令冲突、入口异常、依赖缺失）。
- 第三方依赖（如 `python-docx`）不在 Runtime 运行环境内时 import 会失败；
  推荐做法是延迟导入并给出友好提示，同时把依赖加入 `pyproject.toml` 的
  extra 并在镜像构建时安装（参见 `Dockerfile` 的 `INSTALL_WORD2PPT`）。
- 任务目录中的 `job.log` 类自建日志写在自己的 `data_dir`，便于排查。
- 常见错误：

| 报错 | 原因 |
|---|---|
| `Command is not declared in plugin.toml` | 注册了未声明的命令名 |
| `Plugin command already registered` | 命令重复注册 |
| `Plugin capability requires manifest permission: X` | capabilities 缺少 X |
| `Built-in plugin API requires a manifest builtins declaration` | builtins 未声明目标插件 |
| `Plugin worker timed out` / worker 崩溃 | setup 阻塞过久或插件抛出未捕获异常 |

## 10. 安全红线（会被 Runtime 强制执行）

- 不得直接读写 Runtime SQLite、QQ 凭据、授权令牌或其他插件的数据目录。
- 不得绕过登录、RBAC、CSRF、审计；管理数据读取也要声明对应权限。
- 禁止 `eval/exec/__import__/open` 等出现在对外生成的执行脚本里
  （如需脚本执行，参考 word2ppt 的 AST 白名单 + 独立 worker 模式）。
- 积分、金额一律字符串/Decimal + `operation_id` 幂等，禁止 float。
- `raw_payload` 仅可用于兼容处理，不得写入日志或对外返回。
