# QQ Runtime 部署教程

本文面向 Runtime 管理员，介绍服务器准备、首次安装、机器人配置、升级、备份和常见排查。推荐使用官方交互式安装脚本；它会生成随机主密钥和管理员初始密码，并按选择部署 Runtime、Next.js 管理台、自动更新器及可选解析服务。

## 1. 部署前准备

- 一台可访问公网的 Linux 主机；建议使用受支持的 64 位架构。
- 建议至少预留 2 核 CPU、2 GB 内存和 10 GB 可用磁盘。只部署核心服务时可以更低，但附加媒体服务会增加资源占用。
- 服务器应能访问所选容器镜像源、GitHub Release 和机器人所需的外部服务。
- 准备 QQ 开放平台机器人。应用凭据可在部署后通过管理台安全配置，不要贴在公开 Issue、聊天截图或日志中。
- 默认管理台端口为 TCP `8080`。若更改安装端口，需同步调整防火墙或云安全组。

公网生产部署建议通过 HTTPS 反向代理保护登录 Cookie，并将 `RUNTIME_COOKIE_SECURE` 设为 `true`。不要直接暴露 Docker API、数据库或 sidecar 端口。

## 2. 安装

官方源：

```bash
curl -fsSL https://raw.githubusercontent.com/Chinachani/Runtime-doc/main/install.sh | bash
```

国内网络可用加速源：

```bash
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/Chinachani/Runtime-doc/main/install.sh | bash
```

如需先检查安装脚本：

```bash
curl -fsSLo install.sh https://raw.githubusercontent.com/Chinachani/Runtime-doc/main/install.sh
less install.sh
bash install.sh
```

按提示选择安装目录、外部端口、镜像源和部署档位。核心最小化适合资源较少的主机；媒体增强或全功能档位会额外启动 B 站、抖音或水印处理容器。

安装结束时，脚本会显示管理台地址、初始用户名、初始密码、主密钥和安装目录。请立即将初始密码和主密钥保存在安全的密码管理器或离线位置；它们不会由发行方代为找回。不要将 `.env`、密钥或登录凭据发给他人。

## 3. 首次登录与机器人配置

1. 在浏览器访问安装脚本显示的管理台地址。
2. 使用安装时显示的初始用户名和密码登录；首次登录后建议立即到「系统与管理 → 账户安全」修改密码。
3. 打开「QQ 接入」，按页面提示填写 QQ 开放平台的机器人 AppID、AppSecret 和 Token，然后启动 Gateway。
4. 按交付的授权说明完成机器人绑定，并在管理台运行概览或授权状态页检查结果。
5. 插件可在「插件管理」中从市场安装，或上传作者提供的 ZIP。安装前核对插件来源、权限和签名提示。

## 4. 日常运维

安装目录默认为 `/opt/qq-runtime`，如安装时选择了其他目录，请使用实际路径。常用命令：

```bash
cd /opt/qq-runtime
docker compose ps
docker compose logs --tail=200 runtime
docker compose logs -f runtime
```

只在已配置 HTTPS 反向代理并确认 TLS 正常后，才将 Runtime Cookie 的 Secure 属性设为安全模式；修改 `.env` 后按变更范围重建对应服务。

### 更新

```bash
cd /opt/qq-runtime
docker compose pull
docker compose up -d
```

也可以使用管理台中的版本检查和一键更新。更新期间不要删除 Docker volume 或 `data/` 目录；用户、聊天、插件设置和运行日志保存在持久化数据中。

### 备份与恢复

备份至少应包含安装目录中的 `.env` 和持久化 `data/`。为获得一致的 SQLite 备份，先安排短暂停机：

```bash
cd /opt/qq-runtime
docker compose stop
tar -czf "qq-runtime-backup-$(date +%F-%H%M%S).tar.gz" .env data
docker compose start
```

将备份复制到与服务器不同的安全位置，并确认备份文件可读取。恢复前先停止服务、备份当前目录，再恢复 `.env` 与 `data/`；不要把旧备份覆盖到仍在运行的数据库上。

## 5. 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 管理台无法访问 | 检查 `docker compose ps`、安装端口、防火墙/云安全组，以及 `docker compose logs --tail=200 runtime`。 |
| 容器反复重启或健康检查未通过 | 查看 Runtime 日志和 `docker compose ps`；不要先删除数据目录。 |
| 镜像拉取失败 | 重新运行部署脚本选择可访问的镜像源，或到安装目录执行 `docker compose pull` 并检查 DNS/出口网络。 |
| QQ Gateway 未连接 | 核对 AppID、AppSecret、Token、机器人开放平台配置和服务器出站网络。 |
| 插件无法安装或启用 | 阅读管理台显示的权限、签名、兼容版本与沙箱错误；使用可信来源的插件包。 |
| HTTPS 下反复登录或 Cookie 不生效 | 检查反向代理是否保留 `Host` 与转发协议，并确认 `RUNTIME_COOKIE_SECURE=true`。 |

提供日志寻求帮助前，先遮盖密码、主密钥、Token、Cookie、API Key、机器人凭据和用户隐私。
