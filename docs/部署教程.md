# 部署教程

从零部署一个 QQ Runtime 机器人实例。前置条件：一台能访问公网的 Linux 主机
（推荐 x86_64），已安装 Docker 与 Docker Compose，并在
[QQ 开放平台](https://q.qq.com) 创建了机器人（拿到 AppID、AppSecret、Token）。

## 1. 准备目录与配置

```bash
mkdir -p /opt/qq-runtime && cd /opt/qq-runtime
```

创建 `compose.yaml`：

```yaml
services:
  runtime:
    image: ghcr.io/chinachani/qq-runtime:latest
    container_name: qq-runtime-runtime-1
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      RUNTIME_HOST: 0.0.0.0
      RUNTIME_COOKIE_SECURE: "false"   # 管理台走 HTTPS 时改为 true
      RUNTIME_LICENSE_API_BASE_URL: https://v.567.wiki
      RUNTIME_LICENSE_AUTH_DOMAIN: sq.567.wiki
      RUNTIME_LICENSE_APP_ID: "1"
      RUNTIME_LICENSE_APP_KEY: "<向发行方获取>"
    volumes:
      - ./data:/app/data
```

> 授权相关三个值（APP_ID / APP_KEY / 机器人绑定）由发行方在授权站为你开通，
> 随授权交付。`RUNTIME_LICENSE_AUTH_DOMAIN` 必须保持原样，不要改成 API 地址。

## 2. 启动

```bash
docker compose up -d
docker compose logs -f        # 看到 QQ WebSocket 连接成功即正常
```

浏览器访问 `http://<主机IP>:8080`，用 `.env`/compose 里的管理员账号登录管理台。

## 3. 配置机器人

1. 管理台 → QQ 接入：填入开放平台的 AppID / AppSecret / Token，启动网关。
2. 把机器人的**官方机器人 ID（AppID）**提供给发行方完成授权绑定。
3. 发送 `/license` 确认授权状态为 authorized。

## 4. 更新

```bash
docker compose pull
docker compose up -d
```

管理台「关于/更新」会自动检查新版本并展示更新日志；数据（SQLite、媒体、
插件数据）都在 `./data` 卷里，更新不影响。

## 5. 安装插件

管理台 → 插件管理 → 上传插件 ZIP 包。商业插件需携带发行方签名
（`X-Plugin-Signature`），随插件交付说明一起提供。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 授权状态长期 offline_grace | 检查主机到授权 API 的网络连通性（代理/防火墙），必要时在代理软件中将授权域名设为直连 |
| 授权校验报 HMAC mismatch | `RUNTIME_LICENSE_AUTH_DOMAIN` 未配置或填错，保持与本文一致 |
| 插件激活被拒要求厂商签名 | 商业插件必须使用发行方签发的包，联系发行方获取 |
| 发文件报 file_info is required | 插件未走媒体三步链路，属于插件实现问题，反馈插件作者 |
