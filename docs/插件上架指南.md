## 1. 上架准入与安全规范

为了保障所有机器人实例的安全与稳定，提交至官方插件市场的插件必须符合以下标准：

- **开源与可信**：插件源码必须公开托管在公开代码仓库（如 GitHub / Gitee），提供清晰的 README 说明与开源许可证；
- **沙箱隔离合规**：不得尝试利用漏洞逃逸沙箱，严禁调用未经声明的系统敏感 API，严禁在宿主文件系统执行非法读取；
- **权限最小化原则**：仅声明插件业务实际必需的权限与能力，不可过度索权；
- **无恶意行为**：严禁内置任何后门、挖矿脚本、静默扣费、强制收集用户隐私等恶意代码；
- **稳定交付**：ZIP 安装包根目录下必须包含合法的 `plugin.toml` 与入口文件，且解压体积不可超过 50MB。

## 2. market.json 元数据格式标准

插件市场的官方清单为 [`plugins/market.json`](https://raw.githubusercontent.com/Chinachani/Runtime-doc/main/plugins/market.json)。每个插件条目的结构如下：

```json
{
  "id": "plugin.translator",
  "name": "智能翻译服务",
  "version": "1.0.0",
  "author": "开发者昵称",
  "category": "utility",                 // 分类：ai / utility / tools / entertainment
  "icon": "🌐",                         // 展示 Emoji 图标
  "description": "多语言实时智能翻译插件，支持文本翻译、语种检测与快捷群内指令交互",
  "min_runtime_version": "0.7.0",       // 最低兼容的 Runtime 版本号
  "download_url": "https://raw.githubusercontent.com/username/repo/main/release/plugin.translator.zip",
  "proxy_download_url": "https://gh-proxy.com/https://raw.githubusercontent.com/username/repo/main/release/plugin.translator.zip",
  "sha256": "4a7d...（64位小写十六进制字符串）",
  "permissions": ["network", "chat.send"],
  "size_bytes": 28450,
  "tags": ["翻译", "语言", "工具", "实用"]
}
```

### 字段说明表

| 字段 | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | `string` | 是 | 唯一插件 ID，须与 `plugin.toml` 中的 `[plugin].id` 一致 |
| `name` | `string` | 是 | 插件中文展示名称 |
| `version` | `string` | 是 | 符合语义化版本的版本号（如 `1.0.0`），须与清单一致 |
| `author` | `string` | 是 | 作者昵称或团队名称 |
| `category` | `string` | 是 | 分类标签：`ai`（AI类）、`utility`（实用工具）、`tools`（管理运维）、`entertainment`（娱乐） |
| `icon` | `string` | 是 | 插件卡片展示的 Emoji 图标（如 `🎨`, `📊`, `🤖`） |
| `description`| `string` | 是 | 简明扼要的中文功能介绍（80字以内最佳） |
| `min_runtime_version` | `string` | 是 | 插件正常运行所需的最低 QQ Runtime 版本（如 `0.7.0`） |
| `download_url` | `string` | 是 | 插件 ZIP 包的公开直链下载地址（如 GitHub Release 资源链接） |
| `proxy_download_url` | `string` | 是 | 国内加速镜像下载地址（通常以 `https://gh-proxy.com/` 前缀包装） |
| `sha256` | `string` | 是 | 交付 ZIP 安装包的真实 SHA-256 校验和（全小写 64 位） |
| `permissions` | `list` | 否 | 所需权限清单，用于在安装/更新前向用户展示安全授权确认 |
| `size_bytes` | `int` | 是 | ZIP 压缩包的精确文件字节大小 |
| `tags` | `list` | 否 | 检索标签（方便用户在插件市场中按标签筛选） |

## 3. 提审途径一：框架管理台内置一键提审（推荐）

如果您已经在本地部署的 QQ Runtime 中成功运行并调试了该插件，这是**最简单、零差错**的提审方式：

1. **进入管理台**：
   打开机器人控制台 ➔ **「插件管理」** ➔ 找到您的已安装外部插件卡片；
2. **发起提审**：
   在卡片操作菜单中点击 **「🚀 申请发布到市场」**；
3. **本地自动预检与打包**：
   - 框架会自动读取您的 `plugin.toml`、剔除开发调试垃圾文件并自动重新打包；
   - 框架自动在本地运行沙箱安全预检，并计算出精确的 **SHA-256** 与 **字节大小**；
4. **一键唤起提交**：
   - 弹窗中补全您的 GitHub 仓库直链与 Release ZIP 下载链接；
   - 点击 **「⚡ 一键打开 GitHub Issue 提交」**，浏览器将自动打开 GitHub 页面，**所有标题、版本、哈希、权限和元数据均已自动预填完毕**；
   - 点击 GitHub 页面右下角的 `Submit new issue` 绿色按钮即可完成提审！

## 4. 提审途径二：GitHub Issue 网页填表提审

如果您不方便使用本地管理台，也可以直接通过公开仓库网页提交：

1. 打开公开文档仓库：[`Chinachani/Runtime-doc/issues`](https://github.com/Chinachani/Runtime-doc/issues)；
2. 点击 **「New issue」** ➔ 选择 **「🚀 提交新插件 / 更新插件 (Plugin Submission)」**；
3. 按表单要求填写：
   - 插件 ID、名称、版本、作者；
   - GitHub 源码仓库地址；
   - 公开 Release ZIP 下载地址；
   - 交付 ZIP 的 SHA-256 哈希值；
4. 点击提交，GitHub Actions 机器人将全自动拉取该包进行安全检测与静态分析。

---

## 5. 提审途径三：GitHub Pull Request 提审

适合习惯 Git 操作的开源开发者：

1. Fork 官方仓库 [`Chinachani/Runtime-doc`](https://github.com/Chinachani/Runtime-doc)；
2. 在自己的分支上修改 `plugins/market.json`，按规范追加您的插件对象条目；
3. 发起 Pull Request 提交至 `main` 分支；
4. PR 发起后，CI 机器人将自动对修改项运行验证并在 PR 内给出详细审查结论。

---

## 6. 自动化审核与上架流程

提交成功后，自动化流程如下：

```
开发者发起提交 (Issue / PR / 控制台一键提交)
                │
                ▼
GitHub Actions CI 自动流水线接管
  ├─ 1. 下载 ZIP 并校验下载速度与连通性
  ├─ 2. 比对 SHA-256 哈希是否一致
  ├─ 3. 校验 plugin.toml 格式、入口是否存在
  ├─ 4. 扫描依赖是否位于 Runtime 白名单内
  ├─ 5. 检查解压路径安全性（防路径穿越）
  └─ 6. 机器人自动在 Issue/PR 中发表审查报告
                │
                ▼
官方维护者 Review 并批准
  └─► 审核通过后合并代码，自动化脚本将新插件写入市场
                │
                ▼
全球各节点 QQ Runtime 客户端实时刷新，一键安装上线！
```
